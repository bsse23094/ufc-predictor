# Implementation audit — 2026-10-08

This audit compares the repository with `REQUIREMENTS.md`, `API_SPECIFICATION.md`,
`IMPLEMENTATION_ROADMAP.md`, and the claims in `CURRENT_PROGRESS.md`. It describes
the current worktree, including uncommitted files. It does not certify a release.

## What works

| Area | Code and evidence | Assessment |
| --- | --- | --- |
| Governed historical data | M3 materialization, accepted report, tests under `tests/data/` | Accepted local generation exists. Data and reviewer evidence are ignored local artifacts and must be recreated for a clean checkout. |
| Winner model | M4 bundle and `ChampionRuntime`; `POST /api/v1/predictions/fight`; `tests/ml/test_m5_champion_inference.py` | Strict-date, symmetric pure winner inference is implemented for known canonical fighters using accepted historical rows or a runtime pre-fight vector. |
| Catalog | PostgreSQL models and read-only Parquet fallback for fighters/fights | Local catalog works when accepted M3 artifacts exist. The Parquet path is not a substitute for durable product storage. |
| Web | Next.js pages, typed query hooks, API client | Builds and displays real API data or unavailable states on primary pages. No offline estimate is generated by the API client. |

## Documented release requirements still open

| Requirement | Gap in implementation |
| --- | --- |
| PRD-002/003, ML-004, ML-009 | No accepted method, round, duration, or full uncertainty model bundle. The matchup response now returns null for unsupported method and round outputs. Monte Carlo method/duration draws use illustrative fixed priors. |
| PRD-006, ML-003 | No separately evaluated market model. Matchup requests accept only `pure`; market odds cannot silently substitute for model probabilities. |
| PRD-007, API-003, OPS-002 | `PredictionRepository` is process memory, with no migration-backed immutable prediction snapshot. `persist=true` returns 501. Historical snapshot retrieval is therefore incomplete. |
| API-004/005, OPS-005 | Rate limits and durable async job tracking/scheduling are absent. Worker inference/simulation functions perform computation, but job state lives in process memory and scheduled card snapshots are unimplemented. |
| M8 latency gate | A local first-time runtime feature build for a 2026-10-09 matchup of two known fighters took 15.6 seconds end-to-end in a CLI probe. The route's stated 1.5-second p95 target has not been shown for new dates/pairs. The load fixture chiefly exercises existing historical rows. |
| API-006, OPS-001/003/004, SEC-003/004 | Admin ingestion, model stage/promote/rollback, and quality issue resolution have no durable workflow and return 501 after authorization. Deployment, observability, restore, dependency scan, and security evidence in the roadmap are not satisfied by environment templates and a dashboard JSON. |
| WEB-001/003/004 | Web build and five unit tests pass, but accessibility, responsive screenshots, and prediction-context visual review are incomplete. Some secondary fighter/history pages still use presentation defaults for unavailable statistics. |
| DAT-001/009 | The local `data/upcoming.csv` card is dated 2026-04-04 and has no independent schedule authority in the audit. It is now excluded from the upcoming feed. A verified future schedule source is needed. |

## Corrections made in this audit

- Removed hard-coded offline client responses for fighters, events, predictions,
  simulations, explanations, model cards, and freshness. API failures propagate.
- Removed a stale event fallback and odds-based substitute for winner predictions.
  The event route returns 404 when no future local card exists; the list is empty.
- Removed hard-coded win-method and round percentages from the matchup API response.
  Unsupported outputs are null, and the client no longer fills them with constants.
- Replaced hard-coded landing, compare, simulator, events, model, and data-transparency
  content with API-driven states. Removed the static fighter suggestion list.
- Replaced admin routes that returned success without changing state with explicit
  501 responses; corrected quality issue read fields to match the actual schema.
- Fixed repository/schema type mismatches, idempotency-key payload conflicts, and
  type-check errors. Added a future-card fixture and an expired-card regression test.

## Release gate

The predictor is usable locally for **pure winner probabilities on known canonical
fighters with accepted pre-fight history**. It is not the complete product described by the PRD. The
remaining work is substantial and data-dependent: evaluated method/duration and
market models, durable snapshots/jobs/admin workflows, an audited live schedule,
and deployment/accessibility evidence. Do not publish or label M7–M14 complete
from the older progress log without meeting their roadmap acceptance criteria.
